## 0. G2 范围与结论摘要

G2 只定义首个可玩 MVP 所需的内容和验证数据：

- 6 种食材；
- 6 道互不重复的料理；
- 3 个订单；
- 1 种主要锅具：基础研究锅；
- 1 套确定性配方判定；
- 1 套教学棋盘样例；
- 配方冲突、三投料可达性和试玩观察方法。

六道料理的固定职责：

| 类型 | 料理 | 验证职责 |
| --- | --- | --- |
| 正常目标 1 | 番茄炒蛋 | 两种食材、真实数量、主动开火 |
| 正常目标 2 | 香葱土豆饼 | 三次投料、精确停线、三种配比 |
| 正常目标 3 | 田园菌菇汤 | 研究线索、比例推理、未知菜谱发现 |
| 兜底料理 | 暖锅杂烩 | 错误输入仍有完整、可解释的料理结果 |
| 黑暗料理 | 黏糊番茄薯团 | 错误料理也能形成有趣收藏反馈 |
| 特殊料理 | 星辉菌菇蛋盅 | 7 连生成灵感、后续采集、特殊配方发现 |

兜底、黑暗和特殊料理是三道不同料理，不互相兼任。

## 1. 设计约束

G2 所有内容必须遵守：

1. 配方只读取最终食材单位、比例、基础研究锅和处理条件；
2. 投料顺序不影响料理身份；
3. 每道正常目标料理都能在 3 个基础投料位内完成；
4. 黑暗料理与特殊料理也必须在 3 个基础投料位内真实触发，便于 MVP 验证；
5. 第 4 临时投料位不是任何料理的必需条件；
6. 同样输入必定生成同样料理；
7. 订单目标身份不参与料理星级计算；
8. 食材标签只用于线索、图鉴和视觉理解，除非配方数据明确引用，否则不自动参与配方判定；
9. 本阶段不增加人物、剧情、长期养成、装修、真实商业化和第二种锅具。

## 2. 六种食材

### 2.1 食材总表

| ID | 名称 | 棋盘主色 | 轮廓与内部特征 | 基础标签 | 小尺寸辨识要求 |
| --- | --- | --- | --- | --- | --- |

| ING_CARROT | 胡萝卜 | 明亮橙 | 斜放锥形根茎＋短绿叶 | 清甜、爽脆、蔬菜 | 使用长三角轮廓，是棋盘中唯一明显细长食材 |
| ING_MUSHROOM | 蘑菇 | 浅紫褐＋米白 | 宽伞盖＋短菌柄 | 鲜味、菌香、柔嫩 | 伞盖面积大于柄，使用紫褐色与土豆拉开差异 |
| ING_SCALLION | 香葱 | 青绿色 | 三根束状葱段＋白色根部 | 葱香、调味、点缀 | 纵向束状轮廓，不能只画成一片普通绿叶 |

### 2.2 视觉辨识规则

- 六种食材必须同时依靠**颜色、外轮廓、内部符号**三层区分；
- 不使用单纯换色的同一底模；
- 普通食材使用饱满果冻材质，但表面高光不能遮挡内部识别特征；
- 灵感食材沿用原食材主体，只增加金色星标、双层光圈和轻微跳动；
- 色弱辅助默认保留轮廓和内部符号，不把颜色作为唯一信息；
- 棋盘格内不常驻文字名称，长按或教学提示时才显示名称。

### 2.3 标签的 MVP 用途

基础标签只用于：

- 研究订单的文字线索；
- 食材图鉴描述；
- 玩家对配方关系的理解；
- 后续数据分析时给偏离输入归类。

G2 不制作标签自动合成系统。例如“酸香＋醇厚”不会脱离配方表自动生成新料理。

## 3. 六道料理

### 3.1 通用字段定义

| 字段 | 含义 |
| --- | --- |
| 必需食材 | 配方必须出现的食材及实际入锅单位范围 |
| 禁止食材 | 只要实际入锅单位大于 0，当前配方立即失配 |
| 接受比例 | 配方身份成立所允许的比例范围 |

| 配方优先级 | 多道配方同时合格时的确定性裁决值，数值越大越先 |
| 兜底关系 | 未命中该配方时是否继续匹配其他明确配方或最终进入兜底 |

所有未列入某道明确配方“必需食材”的食材，默认都属于该配方的禁止食材。

## 4. 配方判定与星级数值

### 4.1 配方判定伪规则

料理身份按以下顺序确定：

1. 读取锅中六种食材的最终实际单位；
2. 读取基础研究锅和处理条件集合；
3. 逐道检查除兜底以外的五道明确配方；
4. 必需食材、禁止食材、数量范围、比例和硬性处理条件必须全部成立；
5. 将全部合格配方按优先级降序排列；
6. 优先级相同时按稳定配方 ID 升序选择；
7. 没有明确配方合格时生成暖锅杂烩。

当前六道配方经过食材集合隔离，正常情况下不会同时命中两道明确配方；优先级仍保留，用于防止后续配置调整产生不确定结果。

### 4.2 数量与比例匹配分

对存在理想值的明确配方：

1. 每种必需食材计算与理想单位的绝对差；
2. `总单位偏差 D = 各必需食材绝对差之和`；
3. `数量分 = max(0, 100 − 12.5 × D)`；
4. 实际比例位于理想比例带时，比例分为 100；
5. 实际比例只位于接受比例带时，比例分为 80；
6. `配方匹配分 = 数量分 × 70% ＋ 比例分 × 30%`。

料理身份已经要求实际数值处于接受范围；星级只评价在接受范围内离理想值有多近。

暖锅杂烩没有理想值，配方匹配分固定为 50。

### 4.3 处理质量分

每次有效投料先得到一个处理分：

| 本次连接格数/情况 | 投料处理分 |
| --- | ---: |
| 3～4 格普通连线 | 60 |
| 5～6 格 | 80 |
| 7～8 格 | 90 |
| 9 格及以上 | 100 |
| 本次路径采集到灵感食材 | 在对应档位上＋10，最高 100 |

`本锅处理质量分 = 本锅各次投料处理分的算术平均值`。

处理分影响星级，不替代配方数量、比例和特殊料理的硬性条件。

### 4.4 步数效率分

步数效率读取当前订单配置的剩余步数阈值，不读取料理是否为订单目标：

| 开火时剩余步数 | 效率分 |
| --- | ---: |
| 达到该订单“高效阈值” | 100 |
| 未达到高效阈值，但达到“合格阈值” | 70 |
| 低于合格阈值 | 40 |

### 4.5 星级总分

`星级总分 = 配方匹配分 × 60% ＋ 处理质量分 × 25% ＋ 步数效率分 × 15%`

| 总分 | 当次星级 |
| ---: | --- |
| 85～100 | 3 星 |
| 65～84.99 | 2 星 |
| 0～64.99 | 1 星 |

同一锅输入在同一订单配置中，无论是否为订单目标，三个分项和最终星级都必须相同。

### 5.2 ORD_01「熟悉一下基础研究锅」

**目标**：完成番茄炒蛋。

**显示信息**：

- 直接显示目标料理名称与成品小图；
- 显示番茄建议 4～6、鸡蛋建议 3～5；
- 首次连线前提示“每个格子都会变成 1 单位食材”；
- 番茄连到第 5 格时提示“现在是 5 单位，可以松手”；
- 完成两次投料后高亮“开火”，但不自动触发。

**不显示**：内部评分公式、精确星级阈值、其他三种食材的配方用途。

### 5.3 ORD_02「三份投料，一张香饼」

**目标**：完成香葱土豆饼。

**显示信息**：

- 目标料理已经发现，显示建议范围：土豆 5～7、鸡蛋 3～4、香葱 3～4；
- 提示“这道料理正好需要三次投料”；
- 土豆连到 6 格时只显示数量与轻反馈，不再弹出强制手把手提示；
- 锅中始终显示三类食材的实际单位。

**教学职责**：观察玩家是否能从 ORD_01 的强教学迁移到自主停线。

### 5.4 ORD_03「研究记录：森林里的暖香」

**目标**：内部目标为田园菌菇汤，玩家开始时尚未发现该菜谱。

**显示线索**：

- “菌香是主角”；
- “需要一种清甜根茎和一种绵密根茎”；
- “菌菇的量应接近另外两种食材总量，但不要超过它们”；
- 显示基础研究锅图标；
- 不显示准确数量、料理名称或成品全图。

**可选研究提示**：玩家首次做出暖锅杂烩后，可展开一次免费文字提示：“三种食材都需要，试试让菌菇保持在 4～6 单位。”这属于教学提示，不改变棋盘和数值。

**隐藏发现机会**：当局同时存在蘑菇和鸡蛋，可通过 7 连生成并采集灵感蘑菇，发现星辉菌菇蛋盅。它不是当前订单目标，揭晓后若仍有步数则清锅、保留棋盘继续研究订单。

### 5.5 灵感食材首次提示

玩家存档中第一次生成任意灵感食材时，显示一次非阻塞教学提示：

> 灵感食材：连接时占1格，入锅时算2份。

表现与触发规则：

- 提示同时并排展示一个普通蘑菇和一个灵感蘑菇，用“1格”和“2份”做视觉对比；
- 提示锚定在新生成的灵感食材附近，不使用全屏弹窗，不暂停棋盘动画；
- 玩家可以继续观察棋盘，轻触提示或短暂显示后收起；
- 提示只在首次生成时展示一次，后续不重复；
- 只说明格数与入锅单位，不显示星辉菌菇蛋盅名称、数量答案或隐藏配方；
- 首次提示状态属于存档教学标记，不属于订单或配方数据。

## 7. 三个订单的正确与偏离流程

### 7.1 ORD_01

**正确流程 A**

1. 连接 5 个番茄，剩余 6 步，锅中番茄 5；
2. 连接 4 个鸡蛋，剩余 5 步，锅中鸡蛋 4；
3. 主动开火；
4. 命中 R01，揭晓番茄炒蛋；
5. 订单成功；理想数量与高效阈值下预期 3 星。

**偏离流程 B：加入禁止食材**

1. 番茄 5、鸡蛋 4、蘑菇 3；
2. 开火后 R01 因蘑菇大于 0 失配；
3. 生成暖锅杂烩并正常获得 1～2 星；
4. 若仍有步数，清锅但保留棋盘和剩余步数，继续当前订单；
5. 开始下一锅不扣步数。

**观察点**：玩家能否说出“因为多放了蘑菇，所以不是番茄炒蛋”。ORD_01 不使用香葱作为反例，避免与现实中的常见葱花做法冲突。

### 7.2 ORD_02

**正确流程 A**

1. 土豆 6；
2. 鸡蛋 3；
3. 香葱 3；
4. 主动开火，命中 R02；
5. 剩余 5 步，理想配比下预期 3 星并完成订单。

**偏离流程 B：无脑追求长连**

1. 土豆连接到 9 格；
2. 虽获得大师处理质量，但超过 R02 的 5～7 单位范围；
3. 再加入鸡蛋与香葱后开火，生成暖锅杂烩；
4. 揭晓原因应明确显示“土豆过量”，而不是只写“失败”。

**偏离流程 C：发现黑暗料理**

1. 番茄 7；
2. 土豆 7；
3. 蘑菇 4；
4. 主动开火，命中 R05 黏糊番茄薯团；
5. 完整播放黑暗料理揭晓，记录独立图鉴与星级；
6. 它不是订单目标；若仍有 5 步则清锅续试，不重置棋盘。

**观察点**：黑暗料理是否让玩家产生“虽然做错了，但我发现了新东西”的感受。

### 7.3 ORD_03

**正确流程 A：研究成功**

1. 依据线索连接蘑菇 5；
2. 连接胡萝卜 4；
3. 连接土豆 3；
4. 主动开火，命中 R03 田园菌菇汤；
5. 首次揭晓完整菜名和建议范围；
6. 订单成功并解锁该图鉴条目。

**偏离流程 B：比例错误**

1. 蘑菇 8、胡萝卜 3、土豆 3；
2. 蘑菇数量超过接受范围，即使比例接近也不能命中 R03；
3. 生成暖锅杂烩；
4. 原因提示优先显示“菌菇过量”；
5. 有剩余步数时清锅续试。

**偏离流程 C：发现灵感料理后继续订单**

1. 7 连普通蘑菇，加入 7 单位并在补盘生成灵感蘑菇；
2. 连接 2 个普通蘑菇＋1 个灵感蘑菇，实际再加入 4 单位，蘑菇累计 11并获得灵感条件；
3. 连接 4 个鸡蛋；
4. 主动开火，命中 R06 星辉菌菇蛋盅；
5. 特殊料理完整揭晓、计算星级并进入图鉴；
6. 它不是 ORD_03 的目标，剩余 5 步时清空当前锅，但保留当前棋盘、特殊食材和订单目标；
7. 玩家可用新的 3 次合法连线制作田园菌菇汤；开始下一锅不扣步数。

**观察点**：玩家是否理解灵感食材没有在 7 连时立即加入额外单位，而是在第二次采集时按 2 单位计入。

配置校验要求：若后续调整使两道非兜底配方能同时命中，数据检查器必须报告“配方范围重叠”；运行时仍按优先级和稳定 ID 保持确定性。

### 8.1 静态枚举复核结果

对六种食材各 0～12 单位的整数输入进行了全量枚举，当前配方范围得到：

| 结果 | 数量 |
| --- | ---: |
| 同时命中两道或以上非兜底配方的输入 | 0 |
| R01 合法整数输入组合 | 7 |
| R02 合法整数输入组合 | 11 |
| R03 合法整数输入组合 | 24 |
| R05 合法整数输入组合 | 18 |
| R06 合法整数输入组合 | 6；另须满足灵感条件 |

理想路径按当前星级公式复核：R01 为 92.5 分、R02 为 91.67 分、R03 为 91.67 分、R05 为 95 分、R06 为 93.33 分，均为 3 星。暖锅杂烩即使处理质量和步数效率满分，最高也为 70 分，只能达到 2 星，符合兜底料理定位。

## 9. 三投料可达性检查

| 料理 | 可达投料路径 | 使用投料位 | 是否依赖第4位 | 结论 |
| --- | --- | ---: | --- | --- |
| 番茄炒蛋 | 番茄 5 → 鸡蛋 4 | 2 | 否 | 可达 |
| 香葱土豆饼 | 土豆 6 → 鸡蛋 3 → 香葱 3 | 3 | 否 | 可达 |
| 田园菌菇汤 | 蘑菇 5 → 胡萝卜 4 → 土豆 3 | 3 | 否 | 可达 |
| 暖锅杂烩 | 任意两次合法但未命中明确配方的投料 | 2 | 否 | 可达 |
| 黏糊番茄薯团 | 番茄 7 → 土豆 7 → 蘑菇 4 | 3 | 否 | 可达 |

星辉菌菇蛋盅的三投料可达性依赖棋盘与补充生成条件，因此 ORD_03 特殊验证种子必须保证第二次蘑菇三连可形成；这不是广告槽位或随机暴击。

### 10.2 观察问题

测试人员只观察，不提前解释答案：

1. 玩家是否把连接格数理解成真实投料数量；
2. 玩家看到更长路径时，是否仍会为了配比主动停止；
3. 玩家是否注意投料位，而不只是剩余步数；
4. 玩家是否在开火前读取锅中单位；
5. 玩家能否区分“灵感在棋盘生成”和“灵感被采集后按 2 单位入锅”；
6. 玩家做错后是否理解为什么得到暖锅杂烩或黑暗料理；
7. 非目标料理后保留棋盘继续尝试是否自然；
8. 星级与订单成功/失败分开呈现是否造成困惑。

### 10.3 第一轮内部通过线

第一轮建议至少 8 名未参与设计的玩家。以下仅为 G2 验证阈值，不是长期产品指标：

| 指标 | 暂定通过线 |
| --- | ---: |
| ORD_01 后能说出“1格＝1单位” | ≥ 6/8 |
| ORD_02 至少一次有意识主动停线 | ≥ 5/8 |
| 开火前主动查看锅中内容 | ≥ 6/8 |
| 能基本解释最终料理原因 | ≥ 6/8 |
| 理解灵感格按 2 单位入锅 | ≥ 5/8 |
| 错误料理评价为“有趣/想再试”而非纯挫败 | ≥ 5/8 |
| 三个订单单局时长中位数 | 60～180 秒 |

未达到通过线时，先判断问题来自视觉信息、教学表达、棋盘供给还是数值规则，不能直接用增加弹窗文字解决所有问题。

## 11. 配置数据与程序逻辑边界

### 11.1 交给配置的数据

| 配置文件/数据表 | 内容 |
| --- | --- |
| IngredientConfig | 食材 ID、名称、图标资源、颜色辅助、基础标签、普通/灵感单位价值 |
| BoardConfig | 行列数、连接方向、最低连线数、当局食材种类数、初盘生成策略 |
| RefillConfig | 订单种子、受控食材袋、每列补充队列、目标食材防旱参数 |
| LinkRewardConfig | 5/7/9 阈值、处理分、灵感生成数量和位置策略参数 |
| PotConfig | 基础投料位、临时投料位、最低开火投料数 |
| RecipeConfig | 配方 ID、必需/禁止食材、数量范围、比例、理想值、锅具、处理条件、优先级、稀有度、黑暗标签 |
| OrderConfig | 目标料理、初始步数、五类食材、棋盘种子、线索文本、教学开关、效率阈值 |
| StarConfig | 三项权重、数量偏差系数、处理分、效率分、星级阈值 |
| ResultConfig | 揭晓类型、原因提示优先级、图鉴归类 |
| TutorialConfig | 首次提示 ID、触发事件、提示文本、普通/灵感对比资源、显示方式 |

### 11.2 属于程序逻辑的内容

- 路径相邻校验、同格不可重复、少于 3 格取消；
- 有效连线只消耗 1 步和 1 个投料位；
- 连接格数与实际入锅单位分开计算；
- 普通/灵感食材的单位累加；
- 下落、补盘、死盘检测和免费洗牌；
- 灵感食材按配置位置确定性生成，不覆盖旧格；
- 开火状态机和投料上限；
- 非目标料理后清锅、保留棋盘和剩余步数；
- 配方全条件匹配、优先级与稳定 ID 裁决；
- 星级计算不读取订单目标身份；
- 首次发现、最高星级和黑暗图鉴记录持久化；
- 首次生成灵感食材时读取并写入一次性教学标记，已展示后不重复触发；
- 配方范围重叠、三投料不可达和非法配置的开发期检查。

### 11.3 不能混入程序逻辑的内容

- “番茄炒蛋必须是 5 个番茄＋4 个鸡蛋”这类具体配方；
- 某订单固定 7 或 8 步；
- 灵感固定价值 2 单位；
- 5/7/9 的长连阈值；
- 某种食材固定出现在某一列；
- 某道菜因为是当前订单目标而额外加星。
