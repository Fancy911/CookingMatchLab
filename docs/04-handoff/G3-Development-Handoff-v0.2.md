## 0. G3 的职责与文档优先级

G3 只负责把已经确认的视觉、规则和内容转换为可开发、可测试、可截图、可验收的交接方案，不新增任何产品内容。

后续工程中的解释优先级固定为：

1. 《核心玩法规则 v1.1》负责玩法真值；
2. 《G2 v0.2》负责食材、料理、数值、订单和固定场景真值；
3. 《G1-B 四页面概念方案》负责视觉方向真值；
4. 本 G3 负责工程结构、交互时序和验收口径。

若四份文档出现矛盾，Codex 不得自行选择或修改冻结文档，必须停止相关实现并向项目负责人报告。

G3 通过后，也只代表可以开始首个核心原型的分阶段开发，不代表授权开发完整游戏。

## 1. 首个核心玩法原型的精确范围

### 1.1 原型必须证明的事情

首个核心原型只验证一条完整因果链：

> 玩家连了什么、连了多少  
> → 对应食材真实飞入基础研究锅  
> → 锅中单位和处理条件准确变化  
> → 玩家主动开火  
> → 确定生成一道可解释料理  
> → 目标料理完成订单，非目标料理揭晓后可以清锅续试。

原型通过的核心问题：

- 连线选择是否顺手且数量可控；
- 食材离格、补盘、飞锅和锅中变化是否形成连续因果；
- 玩家是否理解连接格数与实际入锅单位；
- 长连收益和食材过量风险是否同时成立；
- 料理结果能否被配方输入解释；
- 非目标、黑暗和特殊料理是否仍有奖励感；
- 单局能否落在 1～3 分钟。

### 1.2 原型内的玩家可见内容

| 类别 | 原型范围 |
| --- | --- |
| 食材 | 番茄、鸡蛋、土豆、胡萝卜、蘑菇、香葱，共 6 种 |
| 特殊食材 | 6 种食材共用一套灵感视觉规则；G2 固定场景重点验证灵感蘑菇 |
| 料理 | 番茄炒蛋、香葱土豆饼、田园菌菇汤、暖锅杂烩、黏糊番茄薯团、星辉菌菇蛋盅 |
| 锅具 | 仅基础研究锅 |
| 订单 | ORD_01、ORD_02、ORD_03 |
| 棋盘 | 7×7，默认八方向、最低 3 连 |
| 投料 | 3 个基础投料位，至少 2 次投料后主动开火 |
| 长连 | 5/7/9 默认阈值、处理质量、灵感生成、大师处理 |
| 结果 | 确定性配方、1～3 星、订单成功/未完成、非目标续锅 |
| 图鉴数据 | 只保存首次发现和历史最高星级；不制作完整图鉴页面 |
| 测试入口 | O1_TUTORIAL_001、O2_STANDARD、O2_BLACK、O3_STANDARD、O3_INSPIRATION |

核心规则 v1.1 中预留的 Mock 增加步数、第四投料位和其他商业化入口没有被取消，但明确推迟到核心玩法验证之后；首个核心原型不实现这些入口，避免商业流程干扰玩法理解测试。

### 1.3 原型内的最小页面

1. **PrototypeLab 内部场景选择页**：仅开发/验收使用，选择五个固定场景、重置存档、查看测试结果；不作为正式游戏首页。
2. **Battle 核心对局页**：订单、步数、7×7 棋盘、基础研究锅、投料位和开火同屏。
3. **Reveal 料理揭晓覆盖层**：覆盖 Battle，不切换场景，以便非目标料理后保留棋盘继续订单。
4. **Pause 简易暂停层**：继续、重开当前测试场景、返回 PrototypeLab。

### 1.4 原型阶段拆分

| 子阶段 | 目标 | 完成后动作 |
| --- | --- | --- |
| CP0-A | 模块化素材与静态核心对局视觉壳层 | 提交 390×844 运行截图，停下等待确认 |

## 2. Cocos Creator＋TypeScript 技术架构

### 2.1 技术选型结论

| 项目 | 选择 |
| --- | --- |
| 引擎 | Cocos Creator 3.8 LTS；创建工程时锁定实际安装的 3.8.x 补丁版本 |
| 语言 | TypeScript |
| 游戏类型 | 纯 2D Sprite/UI，不使用实时 3D |
| 设计分辨率 | 390×844，竖屏 |
| Canvas 适配 | Fit Width；背景允许纵向延展，交互元素使用 SafeArea/Widget |
| 目标帧率 | 60 FPS；核心动画不得依赖固定帧数计算规则 |
| 动画 | Cocos Tween＋AnimationClip＋ParticleSystem2D；不引入第三方动画框架 |
| 输入 | Cocos Node 触摸事件；单指路径追踪 |
| 规则测试 | Vitest，Node 环境；只测试不依赖 `cc` 的纯 TypeScript 规则层 |
| 运行验收 | Creator 浏览器预览＋Android Debug 构建冒烟 |
| 数据 | 本地 JSON 配置；固定场景使用明确棋盘和逐列队列 |
| 存档 | `sys.localStorage` 的版本化 JSON；无服务器 |
| 随机 | 玩法逻辑禁止直接调用 `Math.random()`；固定场景使用队列，普通调试使用版本化 PRNG |

选择 3.8 LTS 的原因：官方将 3.8 标记为 LTS，并建议新项目使用 Creator 3.x；3.8 支持 TypeScript 组件、2D/UI、跨平台构建和 Android 发布。工程创建后不得在原型中途擅自升级引擎补丁版本。

### 2.2 分层结构

| 层 | 允许依赖 | 职责 |
| --- | --- | --- |
| Domain | 纯 TypeScript，无 `cc` import | 棋盘、路径、投料、配方、星级、订单与存档数据规则 |
| Application | Domain | 接收命令、推进状态机、生成新快照与表现计划 |
| Presentation | Application＋Cocos `cc` | 触摸、节点、Sprite、Label、Tween、粒子、音频和覆盖层 |
| Infrastructure | Domain/Application | JSON 读取、localStorage、调试场景、日志和测试报告 |

强制数据流：

> 触摸输入  
> → Application 命令  
> → Domain 原子结算  
> → 返回新快照＋EffectPlan  
> → Presentation 播放表现  
> → 动画完成回执  
> → 状态机允许下一次输入

UI 动画不得逐帧修改规则真值。规则结果在合法连线松手时一次性计算，表现层只负责把已经确定的结果演出来。

### 2.3 不采用的技术

- 不使用 React/Vue/HTML DOM 制作游戏 UI；
- 不使用 ECS、Redux、全局 Service Locator 或第三方状态库；
- 不使用物理引擎计算食材掉落；
- 不使用 Spine、DragonBones 或实时骨骼作为 MVP 必需依赖；
- 不使用远程 Asset Bundle、热更新、服务器或数据库；
- 不引入广告、支付、TapTap SDK 或登录 SDK；
- 不以整张 G1-B 概念图充当运行背景。

### 2.5 适配策略

- 项目设计分辨率为 390×844；
- Canvas 使用 Fit Width，不开启会导致横纵不同倍率的拉伸方案；
- 背景覆盖整个可见区域，允许在更高屏幕上增加顶部/底部厨房环境；
- HUD、订单、底部按钮放在 SafeArea 内；
- 390×844 基线本身保留顶部 44、底部 34 的交互留白；实际设备使用 `max(基线留白, 系统安全区)`，不得把两者简单相加造成整体下移；
- 棋盘宽度固定按设计坐标缩放，不因更高屏幕拉大格子；
- 高屏幕增加棋盘与锅之间的环境留白，短屏优先压缩空隙，不压缩触控格尺寸；
- 除 390×844 外，至少在 360×800 和 412×915 做无重叠冒烟检查。

### 2.6 性能边界

- 基准画面目标 60 FPS；中端 Android 验收平均帧率不低于 55 FPS；
- 单次松手到确认反馈开始不超过 100 ms；
- 连线结算期间不得出现超过 150 ms 的主线程无响应；
- 食材节点使用对象池，不在每次补盘时反复创建销毁全部 49 个节点；
- 9 连以上仍显示每个被采集食材，但通过自适应间隔把飞锅总时长控制在 500 ms 内；
- 首个原型不以复杂 Shader、全屏后处理或实时灯光获得 G1-B 质感。

## 4. 完整对局状态机

### 4.1 顶层状态

| 状态 | 含义 | 允许输入 |
| --- | --- | --- |
| BOOT | 启动、读取配置与存档 | 无 |
| SCENARIO_SELECT | PrototypeLab 选择固定场景 | 选择、重置存档 |
| ORDER_LOADING | 建立订单、棋盘、队列和初始快照 | 无 |
| ORDER_ACTIVE | 当前订单可操作 | 由子状态决定 |
| COOKING | 开火演出与确定性配方结算 | 无 |
| REVEAL | 料理揭晓与收藏写入 | 继续/完成 |
| ORDER_SETTLEMENT | 订单成功或未完成 | 返回 PrototypeLab/重试 |
| PAUSED | 暂停表现与输入 | 继续/重开/返回 |

### 4.2 ORDER_ACTIVE 子状态

| 子状态 | 进入条件 | 行为 | 退出条件 |
| --- | --- | --- | --- |
| READY | 棋盘稳定且仍可投料 | 接受触摸；开火满足条件时可点击 | 触摸食材→LINKING；点击开火→COOKING |
| LINKING | 按住合法起点 | 追踪同类相邻格、允许回退末格 | 松手→VALIDATING；暂停取消当前路径 |
| VALIDATING | 松手 | 校验方向、同类、重复格与最小连线 | 无效→CANCELING；有效→COMMITTING |
| CANCELING | 少于3格或路径无效 | 路径回缩，不扣步、不投料 | 反馈结束→READY |
| COMMITTING | 合法连线 | Domain 原子扣步、占投料位、算单位、生成 EffectPlan | 真值结算完成→ANIMATING_THROW |
| ANIMATING_THROW | 已有 EffectPlan | 离格、飞锅、重力、补盘、锅反馈 | 所有并行动画到达同步点→SPECIAL_CHECK |
| SPECIAL_CHECK | 补盘完成 | 生成灵感、首次提示、更新处理标签 | 完成→DEAD_CHECK |
| DEAD_CHECK | 棋盘稳定 | 检测是否仍有合法路径 | 死盘→AUTO_SHUFFLE；否则→POST_ACTION |
| AUTO_SHUFFLE | 死盘 | 免费确定性洗牌，不扣步、不改锅 | 洗牌动画完成→DEAD_CHECK |
| POST_ACTION | 单次投料全部完成 | 检查步数、投料位和开火资格 | 按规则进入 READY、POT_REVIEW 或 STEP_EXHAUSTED |
| POT_REVIEW | 已达投料上限但可开火 | 棋盘只读，可查看锅并点击开火 | 点击开火→COOKING |
| STEP_EXHAUSTED | 步数为0 | 棋盘只读，不自动开火 | 已投料≥2可开火；否则订单未完成 |

### 4.3 关键转换

```text
READY
 ├─ 少于3格松手 → CANCELING → READY
 ├─ 合法连线 → COMMITTING → ANIMATING_THROW
 │                         → SPECIAL_CHECK
 │                         → DEAD_CHECK
 │                         → POST_ACTION
 │                            ├─ 可继续投料 → READY
 │                            ├─ 投料位满 → POT_REVIEW
 │                            └─ 步数为0 → STEP_EXHAUSTED
 └─ 主动开火（投料≥2） → COOKING → REVEAL

REVEAL
 ├─ 目标料理 → ORDER_SETTLEMENT.SUCCESS
 ├─ 非目标且剩余步数>0 → 写入发现/星级 → 清锅 → READY
 └─ 非目标且剩余步数=0 → ORDER_SETTLEMENT.NOT_COMPLETED
```

### 4.4 状态机强制约束

- 无效短连不得改变步数、棋盘、投料位、锅或 PRNG 状态；
- COMMITTING 后到 POST_ACTION 前锁定新触摸；
- 第 3 次投料后不自动开火；
- 开火不消耗步数；
- 料理身份在进入 COOKING 时由确定输入一次算出，不在揭晓动画中随机；
- 星级不读取当前订单目标身份；
- 非目标续锅只清空锅中单位、处理标签和投料次数；保留棋盘、灵感格、剩余步数、订单目标和队列位置；
- 死盘洗牌是系统恢复状态，不弹出广告或消耗道具；
- 首次灵感提示为附着在表现层的一次性提示，不阻塞状态机。

### 4.5 暂停与前后台切换

- READY 状态暂停：直接冻结输入与时间线；
- LINKING 状态暂停或应用进入后台：取消当前未提交路径，不扣步、不改变任何真值；
- ANIMATING_THROW、AUTO_SHUFFLE、COOKING 和 REVEAL 演出中暂停：冻结当前 Tween/Animation/Particle/Audio 进度，恢复后从同一进度继续；
- 暂停恢复不得重复触发动画完成回调、重复入锅、重复保存或重复结算；
- “重开当前场景”重新加载固定初盘和队列，不保留当前锅，但已经产生的发现记录仍按存档规则保留；
- 返回 PrototypeLab 时不保存进行中的订单。

## 5. 连线到料理揭晓的交互时序

### 5.1 连线拖动

| 时机 | 表现与规则 |
| --- | --- |
| TouchStart | 起点食材上浮至 1.06 倍；同类候选保持亮度，其他格压暗约 25% |
| 进入合法相邻格 | 节点加入路径；连接线在食材下方延长；显示当前连接格数 |
| 进入不同食材 | 不加入路径；终点轻微左右摆动，不直接取消整条路径 |
| 回到倒数第2格 | 撤销路径末尾1格，数量同步减少 |
| 尝试经过已选非末尾格 | 不重复计数；轻微无效反馈 |
| 达到 5/7/9 格 | 分别播放短切配、灵感、高手三档反馈；不自动松手 |
| 灵感格加入路径 | 格数只＋1；单位预告按配置价值增加，显示如“3格 / 4份” |

连线宽度 9 px，节点直径 15 px，主色 `#FFE28A`，线位于食材 Sprite 下、格子底之上。

### 5.2 无效松手

| 时间 | 表现 |
| ---: | --- |
| 0～70 ms | 路径末端轻缩 |
| 70～170 ms | 连接线反向收回，食材回到 1.0 倍 |
| 170～220 ms | 画面亮度恢复，重新允许输入 |

不显示失败弹窗，不播放刺耳音效，不消耗步数。

### 5.3 有效连线、飞锅与补盘

以松手为 `T=0`：

| 时间 | 规则/表现 |
| ---: | --- |
| 0 ms | Domain 原子生成结算结果和 EffectPlan；输入锁定 |
| 0～100 ms | 选中路径金色确认脉冲，步数数字开始变化 |
| 80～220 ms | 被采集食材上浮、离开格位，原格变空 |
| 180～620 ms | 食材沿一条弧形轨迹依次飞入锅；按路径顺序错峰，全部真实食材均出现 |
| 330～680 ms | 上方食材下落，新食材从顶部补入；不触发自动消除 |
| 540～760 ms | 每颗食材入锅产生小型对应色飞溅；锅中模块数量随入锅节奏增加 |
| 620～800 ms | 锅体轻压回弹，当前投料灯点亮，投料托盘写入格数与单位 |
| 700～860 ms | 如达到灵感阈值，在确定补格出现星标与双环；首次生成同时出现非阻塞提示 |
| 820～920 ms | 死盘检测；必要时进入自动洗牌 |
| 920～980 ms | 所有视觉状态与 Domain 快照一致，解除输入锁定 |

长路径使用自适应错峰：`stagger = clamp(420 / 路径格数, 24, 55) ms`，防止 9 连以上拖慢整局。

### 5.4 自动洗牌

| 时间 | 表现 |
| ---: | --- |

| 720～800 ms | 合法路径检测通过，恢复操作 |

### 5.5 开火与烹饪

## 10. 存档范围

### 10.1 SaveDataV1

```json
{
  "schemaVersion": 1,
  "tutorialFlags": {
    "inspirationUnitHintShown": false
  },
  "discoveredRecipeIds": [],
  "bestStarsByRecipe": {},
  "firstResearchRecordIds": [],

  }

```

### 10.2 原型需要保存

- 灵感食材首次提示是否已经展示；
- 六道料理的首次发现；
- 每道料理历史最高星级；
- 首次研究记录；
- 音乐和音效开关。

### 10.3 原型不保存

- 进行中的棋盘、锅、投料位、剩余步数和队列位置；
- PrototypeLab 最后选择的调试场景；
- 金币、经验、体力、道具、广告次数和付费权益；
- 厨房装修、章节、长期解锁和活动；
- 云存档、账号和跨设备数据。

退出或刷新时，进行中的订单重新开始。该限制必须在 PrototypeLab 标注，不能误当成正式产品存档方案。

### 10.4 写入时机

- 料理进入 Reveal 时立即写入首次发现和最高星级；
- 首次灵感提示实际出现时写入提示标记；
- 非目标料理、订单未完成和刷新都不能撤销已经写入的发现记录；
- 存档解析失败时备份原字符串、建立新存档并在调试日志报告，不能让 Battle 白屏。

### 11.1 场景清单

### 11.2 接入入口

- PrototypeLab 中提供五个场景按钮；
- Web 调试构建支持查询参数：`?scenario=O2_BLACK`；
- Android Debug 构建通过 PrototypeLab 选择；
- Release 构建必须剔除或关闭 DebugLayer 和查询参数入口；
- 场景选择不写入正式存档。

### 11.3 确定性要求

- 固定场景优先读取 `initialBoard` 和 `columnQueues`，不得调用 PRNG；
- 队首先落入该列最低新补格；
- 7 连灵感按路径终点列第一个新补格生成；
- 队列耗尽视为配置错误，固定测试不得静默切随机；
- 普通调试模式使用 `xorshift32-v1`＋32位无符号 seed；
- seed、算法版本和配置哈希写入 RunLogger；
- 玩法代码禁止直接调用 `Math.random()`。

### 11.4 自动动作脚本

ScenarioConfig 允许附带仅供测试的动作脚本：

```json
{
  "type": "LINK",
  "path": [[0, 0], [0, 1], [1, 1]],
  "expect": {
    "stepDelta": -1,
    "potUnits": {"ING_TOMATO": 3}
  }
}
```

自动脚本直接调用 Application 命令，不模拟像素级触摸；像素触摸、回退和拖动容错由人工用例验收。

- 订单、棋盘、锅同时清楚可见；

## 17. 完整操作录屏验收要求

### 17.1 必交录屏

| 录屏 | 内容 | 建议时长 |
| --- | --- | ---: |
| V01 基础教学 | 2连取消→番茄5连→鸡蛋4连→主动开火→番茄炒蛋 | 45～75秒 |
| V02 黑暗续锅 | O2_BLACK→黏糊番茄薯团→继续→香葱土豆饼 | 70～120秒 |
| V03 灵感续锅 | O3_INSPIRATION→首次提示→星辉菌菇蛋盅→继续→田园菌菇汤 | 90～150秒 |

### 17.2 录制标准

- 竖屏画面，内容区为 390×844 或等比整数放大；
- 最低 30 FPS，建议 60 FPS；
- H.264 MP4，画面和音效同步；
- 每段一镜到底，不剪掉等待、错误操作或续锅过程；
- 桌面录制应显示触摸/拖动指示但不遮挡格子；
- 录屏中必须看得清剩余步数、投料槽、锅中数量和星级；
- 不允许用加速视频掩盖动画拖沓；
- Android 冒烟至少提供一段实际触摸录屏或设备外拍佐证。

### 17.3 同步交付

- 自动测试报告；
- 五个固定场景的运行日志；
- Creator 版本、构建目标和配置哈希；
- 截图与录屏索引；
- 已知问题清单；
- 试玩观察表空表及首轮填写结果。
