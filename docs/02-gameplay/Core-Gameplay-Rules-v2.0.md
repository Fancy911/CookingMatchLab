# 《料理消消研究所》核心玩法规则 v2.0 变更稿

版本：v2.0  
日期：2026-08-01  
当前性质：已确认的核心循环修订基线；进入 CP0-R0 前置文件  
前置版本：核心玩法规则 v1.1、G2 MVP 内容 v0.2、CP0-C 可玩原型  
视觉方向：G1-B「果冻玩具厨房」  
适用平台：竖屏移动端，基准验收尺寸 390×844

## 0. 本次修订结论

CP0-C 已验证连线、掉落、投料、开火、料理判定和揭晓在技术上成立，但也暴露出核心体验问题：一锅只需 2～3 次有效连线，玩家尚未形成连续消除节奏就已经完成料理，导致游戏更像“配方计算器”，消消乐感、局内节奏和重复游玩动力不足。

v2.0 将首个核心循环调整为“限时连续料理研究局”：

```text
进入限时研究局
→ 连续连线消除并获得分数
→ 每次合法连线形成 1 份投料
→ 4～6 份之间决定开火时机
→ 揭晓料理、记录制作次数与得分
→ 清锅但保留棋盘和剩余时间
→ 更新下一条研究线索
→ 继续制作下一锅
→ 时间结束自动处理当前锅
→ 展示本局料理、研究地图进度与总分
```

本版正式废止 v1.1 的以下实现口径：

- “每个被连线棋盘格等于 1 单位真实投料”；
- “一锅默认 3 次投料”；
- “普通订单以剩余步数作为主要局内限制”；
- “一局主要只制作一道目标料理”；
- “所有已知订单都直接展示准确目标料理和建议数量”。

除上述冲突项外，7×7 棋盘、同类连线、确定性补盘、确定性料理生成、稀有度与星级分离、黑暗料理独立标签等既有原则继续保留。

## 1. 规则状态

### 1.1 正式方向确认项

1. 使用同类食材连线采集，不改回交换三消。
2. 一局采用连续计时，在同一局内可以制作多锅料理。
3. 每次合法连线只形成 1 份对应食材投料，不再按路径格数直接增加配方数量。
4. 连线格数继续影响连线分、处理质量、语音等级和特殊食材生成。
5. 同一道料理一局内可以重复制作，每次均正常计分和累计制作次数。
6. 时间结束时，如果当前锅满足最低开火条件，系统自动开火。
7. 未发现料理只显示研究线索，不直接显示准确菜名、成品图和完整答案。
8. 已发现料理可以在料理研究地图中查看构成、累计制作次数、最高星级和最高得分。
9. 料理生成继续保持完全确定，相同锅中份数与处理标签必须得到相同料理。
10. 加入 `GOOD / GREAT / UNBELIEVABLE` 文字、语音和分数反馈。

### 1.2 MVP 默认值，必须配置化

| 项目 | MVP 默认值 |
| --- | ---: |
| 棋盘 | 7×7 |
| 当局普通食材种类 | 5 类 |
| 连接方向 | 八方向 |
| 最低合法连线 | 3 格 |
| 单次合法连线投料 | 1 份 |
| 单锅最低开火份数 | 4 份 |
| 单锅最大投料份数 | 6 份 |
| 单局有效操作时间 | 90 秒 |
| 连击保持窗口 | 3.0 秒有效操作时间 |
| 时间结束后的当前连线宽限 | 最多 1.0 秒 |
| 普通重复料理快速揭晓 | 约 1.0 秒 |

### 1.3 首轮试玩验证项

- 90 秒是否适合控制在现实时长约 2～3 分钟；
- 一锅 4～6 次消除是否既有节奏又不会拖沓；
- 一局平均是否能制作 3～5 道料理；
- 半盲研究线索是否足以让玩家解释料理结果；
- 长连在不直接增加配方份数后是否仍有足够吸引力；
- 英文语音反馈是否令人兴奋而非吵闹；
- 重复料理计数是否能推动玩家继续游玩；
- 六节点研究地图是否能建立明确收集目标。

## 2. 单局结构

### 2.1 局内计时

- 单局默认拥有 90 秒“有效操作时间”。
- 计时只在棋盘允许玩家思考或连线时流逝。
- 食材飞锅、重力补盘、烹饪、料理揭晓、暂停和系统洗牌期间暂停计时。
- 因动画暂停的时间不计入玩家的 90 秒，避免表现越丰富越吃亏。
- 最后 10 秒进入柔和警示：计时器变为珊瑚色，播放节奏提示，但不使用刺耳失败警报。
- 时间归零不判定整局失败，只结束继续投料的机会。

### 2.2 时间归零处理

1. 如果归零时没有正在连线，立即锁定新的棋盘输入。
2. 如果归零时玩家正在连线，给予最多 1.0 秒松手宽限：
   - 当前路径合法则正常提交并结算；
   - 当前路径不合法或超时则取消，不产生投料。
3. 当前锅已有 4～6 份投料时，自动开火。
4. 当前锅只有 1～3 份投料时，生成“研究半成品”结算：
   - 不进入料理研究地图；
   - 不增加任何正式料理制作次数；
   - 已获得的连线分仍保留；
   - 不播放黑暗料理或正式料理揭晓。
5. 当前锅为空时，直接进入本局总结。
6. 自动开火的正式料理与主动开火料理遵循同一配方、星级、得分、发现和计数规则。

### 2.3 多锅循环

- 每道正式料理揭晓后只清空锅中投料、当前锅处理标签和锅内投料序号。
- 保留棋盘、特殊食材、补盘队列位置、连击状态、总分和剩余时间。
- 每完成一道料理，更新下一条研究线索。
- 时间尚未结束时立即进入下一锅。
- 一局允许重复生成相同料理，没有“本局已做过所以失效”的限制。

## 3. 连线与投料

### 3.1 合法路径

- 玩家按住一个普通或特殊食材开始连线。
- 只能连接相邻同类食材；MVP 默认包括横、竖、斜八方向。
- 路径不得重复经过已选中的非末尾格。
- 回到倒数第二格时允许撤回最后一格。
- 少于 3 格松手为无效短连：不扣时间以外的资源、不改变棋盘、不投料、不改变确定性队列。
- 合法连线提交后，所选食材离格、真实飞入锅中，上方食材重力下落并按固定队列补盘。
- 不发生自动消除，不发生自动连锁入锅。

### 3.2 一次消除等于一份投料

无论合法路径包含 3 格、5 格、7 格还是 9 格，本次配方数量都只增加 1 份对应食材。

示例：

| 玩家操作 | 配方记录 | 其他收益 |
| --- | --- | --- |
| 番茄 3 连 | 番茄 1 份 | 基础连线分、普通处理 |
| 番茄 5 连 | 番茄 1 份 | 更高分、精切处理、GOOD |
| 番茄 7 连 | 番茄 1 份 | 更高分、灵感生成、GREAT |
| 番茄 9 连 | 番茄 1 份 | 最高档处理、UNBELIEVABLE |

表现解释：被连接的食材全部飞入锅中，并在锅中融合为“一份处理完成的投料”。投料托盘显示食材图标、`1份`和本次处理等级，不再显示“5个格子等于5份”。

### 3.3 单锅容量与开火

- 当前锅达到 4 份投料后，开火按钮点亮，玩家可以主动开火。
- 第 4 或第 5 份后，玩家可以继续观察比例并决定开火。
- 加入第 6 份后锅容量达到上限，棋盘停止接受新连线。
- 满锅后给予约 0.6 秒检查反馈，然后自动开火；玩家也可在此期间立即点击开火。
- 满锅自动开火和时间结束自动开火均不额外扣分。
- 开火本身不消耗时间。

## 4. 长连、灵感与处理标签

### 4.1 长连等级

| 路径格数 | 处理等级 | 文字/语音反馈 | 特殊效果 |
| ---: | --- | --- | --- |
| 3～4 | 普通处理 | 不播放英文语音 | 无 |
| 5～6 | 精切处理 | GOOD | 分数加成 |
| 7～8 | 灵感处理 | GREAT | 补盘生成同类灵感食材 |
| 9 及以上 | 大师处理 | UNBELIEVABLE | 大师标签与最高档分数加成 |

阈值、文案、语音事件和处理分必须配置化。

### 4.2 灵感食材

- 7～8 连合法提交后，在补盘新格中生成一个同类灵感食材。
- 默认落点继续采用：优先路径终点列的新补格；没有合资格新补格时按固定列顺序选择。
- 灵感食材在连接路径中仍只占 1 格。
- v2.0 中，采集灵感食材不会让本次投料变成 2 份；本次仍只加入 1 份对应食材。
- 采集灵感食材会给当前锅添加 `INSPIRATION` 处理标签，并提供额外连线分。
- 特殊料理可以把 `INSPIRATION` 作为硬性配方条件。
- 首次生成时继续显示一次非阻塞提示，但文案调整为：

> 灵感食材：连接时仍算1格，入锅会为这一份料理加入灵感。

旧版“入锅时算2份”的提示正式废止。

## 5. 连线分、连击与语音

### 5.1 单次连线分

```text
基础分 = 路径格数 × 10
长度奖励：
3～4格 = 0
5～6格 = 30
7～8格 = 80
9格及以上 = 150

本次连线分 = round((基础分 + 长度奖励 + 特殊食材奖励) × 连击倍率)
```

MVP 默认特殊食材奖励为 50 分。

### 5.2 连击倍率

- 在上一次合法连线结算后的 3.0 秒有效操作时间内提交下一次合法连线，连击数增加。
- 飞锅、补盘、烹饪和揭晓期间连击窗口暂停。
- 无效短连不清空连击，但其消耗的思考时间会使连击自然超时。
- 主动开火和料理揭晓不清空连击；进入下一锅后仍可继续保持节奏。

| 连续合法消除次数 | 倍率 |
| ---: | ---: |
| 1～2 | ×1.0 |
| 3～4 | ×1.2 |
| 5～6 | ×1.5 |
| 7～9 | ×2.0 |
| 10 及以上 | ×3.0 |

倍率只影响连线分，不改变锅中份数、料理身份或星级。

### 5.3 GOOD / GREAT / UNBELIEVABLE

- 5～6 连触发 `GOOD`；
- 7～8 连触发 `GREAT`；
- 9 连及以上触发 `UNBELIEVABLE`；
- 屏幕文字、语音、粒子等级和实际路径长度必须读取同一个确定事件；
- 不允许动画层随机播放更高等级反馈；
- 英文语音默认开启，但必须提供独立语音开关；
- 同一语音事件设置最短 0.8 秒冷却，避免恢复回调或重复事件叠音；
- 连击倍率升级只播放短音阶，不再叠加第二段英文语音。

## 6. 料理生成系统 v2

### 6.1 输入

料理身份只读取：

- 当前锅六种食材的最终份数；
- 当前锅具；
- `INSPIRATION`、`MASTER` 等处理标签；
- 配方优先级和稳定 ID。

不读取：

- 投料顺序；
- 当前研究线索对应的目标料理；
- 随机稀有暴击；
- 玩家是否第一次制作；
- 动画或音效播放结果。

### 6.2 首轮六道料理份数草案

| ID | 料理 | 份数组合 | 硬性条件 | 稀有度/标签 | 优先级 |
| --- | --- | --- | --- | --- | ---: |
| R01 | 番茄炒蛋 | 番茄2、鸡蛋2、香葱1 | 无 | 普通 | 300 |
| R02 | 香葱土豆饼 | 土豆3、鸡蛋1、香葱1 | 无 | 特色 | 300 |
| R03 | 田园菌菇汤 | 蘑菇2、胡萝卜1、土豆1、香葱1 | 无 | 特色 | 300 |
| R04 | 暖锅杂烩 | 任意4～6份且未命中明确配方 | 无 | 普通、兜底 | 0 |
| R05 | 黏糊番茄薯团 | 番茄2、土豆2、蘑菇1 | 无 | 特色、黑暗 | 500 |
| R06 | 星辉菌菇蛋盅 | 蘑菇3、鸡蛋2 | 必须含INSPIRATION | 珍稀 | 600 |

规则：

- 所有未列出的食材份数必须为 0，否则该明确配方失配。
- 首轮五道明确料理均使用 5 份投料，便于理解“配比正确后主动开火”。
- 4 份提前开火和 6 份满锅可以生成暖锅杂烩，为试错提供确定反馈。
- 上表在进入 Codex 前必须重新执行全量整数枚举、配方冲突和固定场景可达性验证。
- 配方 ID 暂时沿用现有 ID，避免不必要的存档和素材迁移；具体配置必须在 CP0-R0 中统一更新。

### 6.3 星级

菜谱稀有度与当次烹饪星级继续分离。

```text
配方准确分：
明确料理 = 100
暖锅杂烩 = 50

单次投料处理分：
3～4格 = 60
5～6格 = 80
7～8格 = 90
9格及以上 = 100
采集灵感食材 = 对应投料额外 +10，最高100

本锅处理质量分 = 各次投料处理分平均值
料理质量总分 = 配方准确分 × 60% + 处理质量分 × 40%
```

| 料理质量总分 | 星级 |
| ---: | ---: |
| 90～100 | 3星 |
| 70～89.99 | 2星 |
| 0～69.99 | 1星 |

- 星级不读取当前研究线索是否匹配。
- 同一锅输入与处理记录必须获得相同星级。
- 暖锅杂烩理论最高为 70 分，最多 2 星。

### 6.4 料理得分

料理得分与星级分开，用于本局总分：

| 项目 | 默认分数 |
| --- | ---: |
| 普通料理基础分 | 500 |
| 特色料理基础分 | 750 |
| 珍稀料理基础分 | 1200 |
| 黑暗标签额外分 | 200 |
| 每颗星 | 200 |
| 首次发现 | 500 |
| 命中当前研究线索 | 300 |

```text
料理得分 = 稀有度基础分 + 黑暗标签分 + 星级分 + 首次发现分 + 研究线索分
本局总分 = 全部连线分 + 全部料理得分
```

重复制作相同料理仍正常获得稀有度基础分和星级分，但不重复获得首次发现分。

## 7. 半盲研究线索

### 7.1 显示原则

- 教学第一锅可以直接显示菜名、食材与份数，确保玩家理解新投料规则。
- 未发现料理只显示食材、风味、颜色、比例或处理方式线索。
- 不显示未发现料理的准确菜名、完整成品图和精确配方。
- 已发现料理可以在研究地图详情中显示准确份数组合。

### 7.2 局内线索更新

- 开局从配置化线索队列中读取第一条线索。
- 每完成一道正式料理，无论是否命中线索，都更新下一条线索。
- 命中线索只提供额外料理分，不阻止玩家制作其他料理。
- 玩家可以忽略线索、重复制作同一道菜或主动尝试隐藏料理。
- 线索队列与固定测试场景必须确定性生成，不使用 `Math.random()` 直接裁决。

### 7.3 首轮线索示例

| 对应料理 | 未发现时线索示例 |
| --- | --- |
| 番茄炒蛋 | 酸甜与嫩滑很相配，再加一点绿色点缀。 |
| 香葱土豆饼 | 绵密根茎要占大头，蛋香负责黏合。 |
| 田园菌菇汤 | 菌香是主角，两种根茎和一点绿色能托住暖味。 |
| 黏糊番茄薯团 | 汁水太多、淀粉也太多，再裹进柔软菌菇会发生什么？ |
| 星辉菌菇蛋盅 | 大量菌香与蛋香之间，似乎还缺一次灵光。 |

## 8. 料理揭晓节奏

### 8.1 完整揭晓

以下情况播放完整揭晓：

- 任意料理首次发现；
- 珍稀料理；
- 黑暗料理首次发现；
- 玩家主动点击快速揭晓中的“展开”。

完整揭晓期间暂停局内计时。

### 8.2 快速揭晓

- 已发现的普通或特色料理默认使用约 1 秒快速揭晓。
- 快速揭晓显示成品、菜名、星级、本次得分和 `累计制作 ×N`。
- 完成后自动清锅、更新研究线索并恢复计时。
- 不能因为追求快节奏而跳过料理计数、存档或地图更新。

### 8.3 重复料理

- 一局内重复料理正常出现，不替换成兜底结果。
- 每次均增加本局次数与历史累计次数。
- 每次均可刷新最高星级和最高料理得分。
- 地图节点在结算时显示本局增量，例如 `番茄炒蛋 +2`。

## 9. 料理研究地图

### 9.1 首版结构

首版地图名称：`基础研究厨房`。

地图以厨房路线、研究台和料理节点组成，不使用网页列表、后台表格或纯文字卡片。首版只放置 6 个料理节点：

- 3 道正常料理节点；
- 1 道兜底料理节点；
- 1 道黑暗支路节点；
- 1 道珍稀隐藏支路节点。

该结构必须能在后续增加中餐、西餐、甜品、烧烤、饮品和节日地图区域，但首版不制作这些区域。

### 9.2 未发现节点

- 显示料理剪影和 `???`；
- 不显示准确配方；
- 黑暗和珍稀支路可以隐藏连接线，避免提前暴露数量；
- 未发现节点不显示虚假“0次制作”数据。

### 9.3 已发现节点

显示：

- 料理成品图；
- 菜名；
- 稀有度和黑暗标签；
- 历史累计制作次数；
- 历史最高星级；
- 历史最高料理得分；
- 准确食材份数组合；
- 是否需要灵感或大师条件。

### 9.4 料理计数

以下结果增加历史制作次数：

- 正常料理；
- 重复料理；
- 暖锅杂烩；
- 黑暗料理；
- 非当前研究线索料理；
- 时间结束自动开火生成的正式料理。

以下结果不增加历史制作次数：

- 1～3 份投料形成的研究半成品；
- 尚未完成配方结算就退出的当前锅；
- 重复执行同一结算回调；
- 调试界面直接展示的静态料理预览。

制作次数在料理身份确定且进入揭晓时写入。每次结果拥有唯一 `cookResultId`，同一 ID 只能累计一次，防止重复回调、恢复和连点造成重复计数。

## 10. 本局结算

时间结束且当前锅处理完成后进入本局总结，至少显示：

- 本局总分；
- 本局制作料理总数；
- 各料理本局制作次数；
- 新发现料理；
- 本局最高稀有度；
- 最长连线；
- 最高连击倍率；
- 料理研究地图新增进度。

本局没有做出正式料理时仍显示连线分和研究半成品说明，不使用严厉失败界面。

## 11. 音频规范

### 11.1 首版音频清单

- 背景音乐：轻松玩具厨房循环 1 条；
- 食材触摸；
- 连线经过格子；
- 无效短连；
- 合法消除确认；
- 食材飞入锅；
- 单颗或单批落料；
- GOOD 英文语音；
- GREAT 英文语音；
- UNBELIEVABLE 英文语音；
- 连击倍率升级短音阶；
- 灵感食材生成；
- 开火按钮；
- 炉火与锅盖；
- 普通、特色、珍稀、黑暗四类揭晓反馈；
- 首次发现印章；
- 地图节点点亮；
- 最后 10 秒节奏提示；
- 本局结算。

### 11.2 播放规则

- 音乐、音效和语音分别提供开关，并持久化设置。
- 语音播放时背景音乐短暂降低音量，不完全静音。
- 同类短音效需要并发上限，避免长连飞锅产生刺耳叠音。
- 暂停和应用进入后台时冻结或暂停音频；恢复不得重复播放已经完成的语音或结算音。
- 所有音频必须为原创、已授权或来源明确的可商用素材；不得抓取来源不明音频。
- 如果 Codex 无法合法取得满足标准的音频，必须报告阻塞，不得用系统提示音或合成蜂鸣冒充最终音效。

## 12. 390×844 对局信息调整

v2.0 保留 G1-B 基础布局，但进行以下调整：

- 原顶部“剩余步数”徽章改为 90 秒计时器；
- HUD 增加当前总分与连击倍率；
- 订单托盘改为“研究线索托盘”，未知料理不显示成品小图；
- 原三个投料槽改为最多 6 份的实体投料记录区，可使用两排三格或六枚小碟；
- 每格显示食材图标与处理等级，不显示棋盘格数量作为配方份数；
- 开火按钮在第 4 份点亮，第 6 份后进入满锅自动烹饪反馈；
- GOOD/GREAT/UNBELIEVABLE 位于棋盘上方或中部，不遮挡当前路径；
- 本局快速揭晓以短覆盖层出现，不能让棋盘重新加载或闪白。

完整像素布局需要在进入 Cocos 修改前单独输出并以 390×844 静态稿验收。
